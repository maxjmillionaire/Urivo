# Specification 7 — Custom Domains (Lovable-style buy & auto-connect)

Status: **DEFERRED — do not implement yet.** Founder decision (see below): build the
full flow in one pass once the prerequisites exist. Nothing is built today.

## 1. Goal

A founder can give their store a real custom domain (`yourbrand.com`) with the
same effortless feeling Lovable delivers: search a domain, buy it in-app with one
click, and have it connect to the store automatically — no DNS copy-pasting, no
leaving Urivo. Plus a "connect a domain you already own" path.

Until this ships, every store lives at its `*.urivo.ai` subdomain (spec 6.7),
which remains the permanent free default.

## 2. Chosen providers (founder decision)

- **Entri** — domain search, pricing, purchase, and automatic DNS configuration
  (the "1-click connect" magic, incl. OAuth auto-config at existing registrars).
- **Cloudflare for SaaS** — on-demand TLS certificate issuance for unlimited
  customer custom domains pointed at Urivo's ingress.
- **Stripe** — customer payment for the domain. This is Phase 2 (founder-owned),
  and is a hard prerequisite.

Keep the integration behind a provider interface (`DomainProvider`) per spec 6.9
so the reseller can be swapped without touching routes or UI.

## 3. Prerequisites (all required before build starts)

1. Entri account + API credentials.
2. Cloudflare for SaaS zone configured for the apex Urivo domain + fallback origin.
3. Stripe live (Phase 2) for charging the domain purchase.
4. Env keys added to `lib/env.ts` as optional until configured:
   `ENTRI_APP_ID`, `ENTRI_SECRET`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ZONE_ID`.

## 4. Data model

New table `custom_domains` (RLS: owner-all; public read only where the parent
store is active, mirroring `stores`/`products`):

- `id uuid pk`
- `store_id uuid fk -> stores(id) on delete cascade`
- `user_id uuid` (denormalized owner for RLS)
- `domain text unique` (normalized, punycode for IDNs)
- `status text` — `pending_purchase | pending_dns | verifying | live | failed`
- `source text` — `purchased | connected`
- `verification_txt text` (for connected domains)
- `provider_ref text` (Entri/registrar order id)
- `created_at`, `verified_at`

## 5. Routing & TLS

- Middleware host resolution (extends spec 6.7): if the request host is not the
  root domain or a `*.urivo.ai` subdomain, look it up in `custom_domains` where
  `status = 'live'`; on hit, rewrite to `/store/{subdomain}` for the mapped store.
  On miss, neutral 404 (never reveal existence).
- TLS is issued by Cloudflare for SaaS via a custom hostname per verified domain;
  ingress presents the cert automatically. No cert handling in app code.

## 6. Flows

### 6.1 Buy through Urivo (the headline experience)
1. Search — `POST /api/domains/search` → Entri availability + price for a query.
2. Purchase — `POST /api/domains/purchase` → create Stripe payment, on success
   register via Entri, auto-configure DNS to Cloudflare for SaaS, insert
   `custom_domains` row `source=purchased`, poll to `live`.
3. Reveal — store instantly reachable on the new domain; status card shows Live.

### 6.2 Connect a domain you already own
1. `POST /api/domains/connect` → insert `pending_dns` row + `verification_txt`.
2. Entri OAuth auto-config at the user's registrar where supported; otherwise the
   status card shows the exact A/ALIAS + CNAME(`www`) + TXT records.
3. `POST /api/domains/verify` → live DNS lookup; on match set `live`.

## 7. Pipeline discipline (per spec 6.1/6.3)

Every route: authenticate → `requireStoreOwner(storeId)` → rate-limit → Zod
validate → provider call → persist. Never trust a domain/store id from the client.
Purchase is server-authoritative and idempotent on the Stripe event; a failed
registration never charges twice and never leaves a dangling `live` row.

## 8. UI

A "Domains" panel in the store manager: current `*.urivo.ai` address (always
free), a search-and-buy field, a "connect existing" option, and a status card
(pending → verifying → live) with copy-ready DNS records when manual.
CTAs use the standard premium gold finish.

## 9. Out of scope for v1

Email hosting on the domain, domain transfers out, and marketplace/aftermarket
premium domains. Renewals are handled by the registrar; surface expiry + renewal
status read-only.
