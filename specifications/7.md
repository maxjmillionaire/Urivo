# Specification 7 — Custom Domains (Lovable-style buy & auto-connect)

Status: **DEFERRED — do not implement yet.** Founder decision: build the full
flow in one pass once the prerequisites exist. Nothing is built today.

## 1. Goal

A founder can give their store a real custom domain (`yourbrand.com`) with the
same effortless feeling Lovable delivers: search a domain, buy it in-app with one
click, and have it connect to the store automatically — no DNS copy-pasting, no
leaving Urivo. Plus a "connect a domain you already own" path.

Until this ships, every store lives at its `*.urivo.ai` subdomain (spec 6.7),
which remains the permanent free default.

## 2. Chosen providers (founder decision — updated)

- **Cloudflare Registrar** — domain search, pricing and purchase **at wholesale
  cost with no markup and no monthly platform fee**. Urivo pays only each
  domain's registration price (which the customer pays at checkout).
- **Cloudflare for SaaS** — on-demand TLS certificate issuance for unlimited
  customer custom domains pointed at Urivo's ingress (custom hostnames). Has a
  free allotment, then low per-hostname pricing.
- **Stripe** — customer payment for the domain (reuse the storefront commerce
  Stripe integration from spec/commerce). Phase 2, founder-owned. Hard
  prerequisite.

Rationale for dropping Entri: Entri's value is auto-configuring DNS for domains a
customer *already owns elsewhere*. When Urivo **sells** the domain, Urivo owns the
DNS zone, so pointing it at the store and issuing TLS is trivial — no third-party
auto-config needed. This removes Entri's fixed monthly platform fee entirely; the
only per-domain cost is the registration itself, which the customer pays.

Entri (or a similar OAuth DNS-config service) is an **optional later add-on**,
only for the "connect a domain you already own" path if we want one-click
configuration at third-party registrars. Not required for launch.

Keep the integration behind a provider interface (`DomainProvider`) per spec 6.9
so the registrar/DNS provider can be swapped (e.g. Vercel Domains if Urivo hosts
on Vercel) without touching routes or UI.

## 3. Prerequisites (all required before build starts)

1. Cloudflare account with **Registrar** access and a **for SaaS** (custom
   hostnames) zone configured for the apex Urivo domain + a fallback origin.
2. Stripe live (Phase 2) for charging the domain purchase.
3. Env keys added to `lib/env.ts` as optional until configured:
   `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_ZONE_ID`.
   (Stripe keys already added for storefront commerce.)

## 4. Data model

New table `custom_domains` (RLS: owner-all; public read only where the parent
store is active, mirroring `stores`/`products`):

- `id uuid pk`
- `store_id uuid fk -> stores(id) on delete cascade`
- `user_id uuid` (denormalized owner for RLS)
- `domain text unique` (normalized, punycode for IDNs)
- `status text` — `pending_purchase | pending_dns | verifying | live | failed`
- `source text` — `purchased | connected`
- `verification_txt text` (for connected domains)
- `provider_ref text` (Cloudflare registration / custom-hostname id)
- `created_at`, `verified_at`

## 5. Routing & TLS

- Middleware host resolution (extends spec 6.7): if the request host is not the
  root domain or a `*.urivo.ai` subdomain, look it up in `custom_domains` where
  `status = 'live'`; on hit, rewrite to `/store/{subdomain}` for the mapped store.
  On miss, neutral 404 (never reveal existence).
- TLS is issued by Cloudflare for SaaS via a custom hostname per verified domain;
  ingress presents the cert automatically. No cert handling in app code.

## 6. Flows

### 6.1 Buy through Urivo (the headline experience)
1. Search — `POST /api/domains/search` → Cloudflare Registrar availability + price
   for a query.
2. Purchase — `POST /api/domains/purchase` → create Stripe payment; on success
   register the domain via Cloudflare Registrar, create the Cloudflare for SaaS
   custom hostname, point DNS at Urivo's ingress, insert `custom_domains` row
   `source=purchased`, poll to `live`.
3. Reveal — store instantly reachable on the new domain; status card shows Live.

### 6.2 Connect a domain you already own
1. `POST /api/domains/connect` → create a Cloudflare for SaaS custom hostname +
   insert `pending_dns` row with a `verification_txt`.
2. The status card shows the exact records to add (CNAME/A to the ingress target
   + the ownership/verification TXT). (Optional future: an Entri-style OAuth
   auto-config popup for supported registrars.)
3. `POST /api/domains/verify` → live DNS lookup / Cloudflare hostname status; on
   success set `live`.

## 7. Pipeline discipline (per spec 6.1/6.3)

Every route: authenticate → `requireStoreOwner(storeId)` → rate-limit → Zod
validate → provider call → persist. Never trust a domain/store id from the client.
Purchase is server-authoritative and idempotent on the Stripe event; a failed
registration never charges twice and never leaves a dangling `live` row.

## 8. UI

A "Domains" panel in the store manager: current `*.urivo.ai` address (always
free), a search-and-buy field, a "connect existing" option, and a status card
(pending → verifying → live) with copy-ready DNS records when manual.
CTAs use the standard premium gold finish.

## 9. Out of scope for v1

Email hosting on the domain, domain transfers out, and marketplace/aftermarket
premium domains. Renewals are handled by the registrar; surface expiry + renewal
status read-only.
