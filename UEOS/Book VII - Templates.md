# BOOK VII — Templates

> "Systems scale through templates.
> Reinventing the process is wasted energy."

---

# Purpose

Templates eliminate inconsistency.

Every recurring process should have a reusable structure.

Templates increase:

- Speed
- Quality
- Consistency
- Predictability

Every important workflow inside Urivo should begin with a template.

---

# Philosophy

Never start from a blank page.

Every project benefits from experience.

Templates capture best practices.

They reduce mistakes.

They accelerate execution.

---

# Discovery Template

Every project begins by answering:

## Business

- What problem are we solving?
- Who is the customer?
- Why does this matter?

## Product

- Primary objective
- User journey
- Success metrics

## Technical

- Constraints
- Risks
- Dependencies

Nothing moves forward without discovery.

---

# Proposal Template

Every proposal contains:

- Executive summary
- Objectives
- Scope
- Deliverables
- Timeline
- Pricing
- Assumptions
- Success criteria

Clear expectations create successful projects.

---

# Specification Template

Every feature specification includes:

## Overview

Purpose of the feature.

## User Problem

What problem is being solved?

## Functional Requirements

Detailed implementation requirements.

## Non-Functional Requirements

- Performance
- Accessibility
- Security
- Scalability

## Acceptance Criteria

How success is measured.

Specifications remove ambiguity.

---

# Architecture Template

Every system design documents:

- Goals
- Components
- Data flow
- APIs
- Dependencies
- Security
- Scalability
- Future considerations

Architecture should always be understandable.

---

# Engineering Template

Before implementation:

- Read specification
- Review architecture
- Identify dependencies
- Estimate complexity
- Define milestones

Engineering begins with planning.

---

# Code Review Template

Review every Pull Request for:

## Readability

Is the code easy to understand?

## Simplicity

Can complexity be reduced?

## Performance

Is the implementation efficient?

## Maintainability

Will future engineers understand it?

## Standards

Does it follow UEOS?

Every review improves the system.

---

# QA Template

Quality Assurance validates:

- Functionality
- User experience
- Responsiveness
- Accessibility
- Performance
- Browser compatibility
- Error handling

Nothing ships without QA.

---

# Launch Template

Before release verify:

- Build successful
- Tests passing
- Environment configured
- Analytics enabled
- Monitoring enabled
- Error tracking active
- Documentation updated

Launches should be boring.

Predictability is success.

---

# Incident Template

When something breaks document:

- What happened?
- Root cause
- Impact
- Resolution
- Lessons learned
- Preventive actions

Every incident improves the company.

---

# Post-Mortem Template

After every major project answer:

- What worked well?
- What failed?
- What surprised us?
- What should change?
- What becomes a new standard?

Knowledge compounds.

---

# AI Prompt Template

Every important AI prompt contains:

## Objective

What should be accomplished?

## Context

Relevant project information.

## Constraints

Rules that cannot be violated.

## Expected Output

What should the response include?

## Quality Standard

Definition of success.

Better prompts create better engineering.

---

# Documentation Template

Every document should contain:

- Purpose
- Context
- Requirements
- Decisions
- Examples
- References
- Revision history

Documentation should outlive its author.

---

# Continuous Improvement

Templates are living systems.

Whenever a better workflow is discovered:

- Update the template.
- Document the improvement.
- Apply it everywhere.

Templates should evolve with Urivo.

---

# Definition of Great Templates

A great template should:

- Save time
- Prevent mistakes
- Improve consistency
- Increase quality
- Scale knowledge

Templates transform experience into systems.

---

> This is the acceleration of Urivo.

Templates allow excellence to be repeated.
